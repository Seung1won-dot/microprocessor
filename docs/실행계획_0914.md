## 1. 제안서 심사(4주차)까지 복원·확정할 것

심사를 통과해야 **부품 발주가 가능**합니다. 아래 4개가 통과 조건입니다.

> 📌 ①②는 **없던 것을 새로 만드는 게 아닙니다.**
> [신청서_요약서](신청서_요약서.md) 원고에 이미 설계되어 있었으나 **제출본에서 분량 때문에 잘려나간 것**이므로,
> 제안서에서 **원래 설계를 복원**하면 됩니다. 제안서는 신청서와 별개 문서라 주제 변경이 아닙니다.

### ① 인터럽트 — 반려 사유 1순위 (**9/21 재설계**)

신청서 기대효과에는 *"인터럽트 기반 실시간 처리"* 가 남아 있는데, 수행 방법 문단에서 빔브레이크가 빠지면서
*"인터럽트여야만 하는 이유"* 가 사라졌습니다.
**9/21에 빔브레이크 자체를 폐기했으므로, 원고의 "출입 카운트" 논거는 쓸 수 없습니다. 전부 새로 세웁니다 — 부품 추가는 0원입니다.**

```
Timer2 CTC (~2ms)   : 7세그먼트 4자리 멀티플렉싱
                      → 자리 전환이 수 ms, delay()로는 깜빡임 + 패킷 유실
Timer1 CTC (1초 틱) : 워치독(마지막 수신 후 경과) · 운영시간 경계(오픈·마감) · 황색 점멸
UART RX 인터럽트    : 호스트 패킷 수신 → 버퍼 적재 + 수신 시각 기록
```

**제안서에 쓸 논거**
> 7세그먼트 4자리를 멀티플렉싱하려면 수 ms 주기로 자리를 전환해야 하는데, 이를 `delay()`로 구현하면
> 그 사이 도착하는 호스트 패킷을 놓친다. 따라서 **표시 스캔은 타이머 ISR이, 수신은 RX ISR이** 담당해야 둘 다 보장된다.

> ⚠️ **오픈·마감은 주 논거로 쓰지 마세요.** 하루 2번이라 *"폴링으로도 잡힌다"* 는 반박이 가능합니다.
> **"1초 틱 인터럽트가 이미 있으니 거기서 함께 처리하는 기능"** 으로 설명하는 것이 안전합니다.

빔브레이크를 뺀 덕에 **부품비 1.5만원이 회수**되고, 기업이 지적한 *"출입구 계수는 남은 자리를 모른다"* 에는
**"그래서 계수를 아예 쓰지 않고 좌석 점유를 직접 본다"** 고 더 깔끔하게 답할 수 있습니다.

> 상세 표는 → [설계변경_0921 3-2절](설계변경_0921.md)

### ② AI 3초 폴백 (**9/21 재설계**)

```
정상          → 검출값으로 3단계 갱신
3초  무갱신   → 마지막 유효값 유지 + 웹에 "갱신 지연" + 경과 시간 표시
15초 무갱신   → EEPROM 요일·시간대별 평균 + "확인 불가(추정)" (보수적 = 더 혼잡한 쪽)
운영시간 밖   → "운영 종료" (혼잡도 표시 안 함)
```

- 원칙: **애매하면 더 혼잡한 쪽으로 표시** (헛걸음 손실이 더 큼 — 손실 비대칭)
- 웹에 *마지막 갱신 시각*을 띄우기로 했으므로 화면 설계와 그대로 맞물림
- **시연 직결**: 라즈베리파이 전원을 뽑아도 아두이노가 자체 시계와 EEPROM 평균만으로 시연 표시부를 계속 구동하는 장면이
  **AI 폴백의 직접적인 증거**가 됩니다 → 9절 시연 항목에 포함

### ③ QR 웹 접속 경로 — 조용한 함정

라즈베리파이가 웹서버를 직접 띄우면 **교내망 안에서만** 열립니다.
QR을 찍는 학생은 LTE로 들어오므로 **접속이 안 됩니다.** 포트 개방은 학교에서 잘 안 해줍니다.

```
라즈베리파이 ──(점유율 숫자만 POST)──→ 외부 무료 호스팅 ──→ 학생 휴대폰 (QR)
   영상은 나가지 않음                     정적 페이지가 값을 읽음
```

- 프라이버시 설명(영상 비전송·온디바이스)은 그대로 유지됨
- ⚠️ 예산으로 **소프트웨어·클라우드 결제 불가** → 반드시 **무료 티어**

### ④ 설치 허가 — 프로젝트 전체가 여기에 걸림

카메라를 천장에 못 달면 남는 게 없습니다. **두 갈래를 동시에** 진행합니다.

1. **운영 주체 확인 후 접촉** (학생복지처 / 위탁업체)
   명분은 "학생 편의"보다 **"좌석 회전율·배식 인력 배치 근거 데이터 제공"** 이 결재가 잘 남
2. **삼각대 임시 설치 + 현장 녹화 영상 리플레이 모드**를 1급 기능으로 개발
   → 학술제 부스에서도 어차피 필요 (식당을 가져갈 수 없음)

## 2. 정확도 — 기업이 짚은 두 가지가 곧 채점 기준

기업 수요내용의 **가림(occlusion)과 조명 변화**가 그대로 평가 축입니다.
모델을 키우는 것보다 **후처리로 얻는 이득이 훨씬 큽니다.**

| 문제 | 대응 |
|---|---|
| 판정 깜빡임 | **히스테리시스** — 점유 진입은 3초 연속, 해제는 10초 연속일 때만 전환 |
| 조명 변화 | 카메라 **노출·화이트밸런스 고정** (자동이면 하루 종일 흔들림) |
| 가림 | 천장 하향 + 2대 시야 **중첩 구역은 좌석 ID 기준 OR 병합** (중복 카운트 방지) |
| 소지품만 둔 자리 | COCO 사전학습 클래스(backpack·laptop·bottle·cup)로 무료로 잡힘 → **"보류" 별도 상태**로 집계 |

### 학습부터 하지 말 것 — 순서가 중요합니다

좌석이 고정이므로:

1. **좌석 ROI를 수동으로 1회 지정**
2. 사전학습 YOLO의 `person` 박스와 **ROI 매칭**만으로 1차 버전 동작
3. 오차를 **측정한 뒤** 필요한 곳만 파인튜닝

> 이 순서를 뒤집으면 11월에 아무것도 안 돌아갑니다. 2인 팀에서는 특히.

### 라벨링이 쉽다는 것이 이 방식의 장점

프레임 단위 박스를 그리는 것이 아니라 **점심에 좌석 체크시트로 O/X를 세는 것**이 정답 데이터입니다.
산출물 ④ **정확도 검증 보고서**가 이 시트에서 그대로 나옵니다.

### 3단계 임계값

- 예: 점유율 <50% 여유 / 50~80% 보통 / >80% 혼잡 (**현장 실측 후 확정**)
- 경계에서 신호등이 진동하지 않도록 **단계 전환에도 히스테리시스** 적용
- **전체 좌석 수는 고정 상수** → 1회 실측으로 확정

> ⚠️ **이 배분안은 9/16 예산 회의에서 규정 검토 후 갱신되었습니다. → [예산회의_0916](예산회의_0916.md) 3절이 최신 금액입니다.**

| 항목 | 금액 |

| microSD 128GB | 20,000 |
| **CSI 카메라 모듈 ×2 (광각)** + RPi5용 22핀 케이블 | 110,000 |
| 시연 표시부 (LED · 7세그먼트 · 74HC595 · 부저 · 배선) | 20,000 |
| 거치대·삼각대·브래킷 ×2 | 60,000 |
| 하우징·가공재 | 40,000 |
| 부스 시연용 좌석 모형 재료 | 30,000 |
| 예비 부품 (카메라 1 · SD · 점퍼/저항) | 70,000 |
| **합계** | **560,000** (여유 40,000) |

### ⚠️ 구매 전 주의 2가지

- **USB 웹캠이 아니라 CSI 카메라 모듈**로 살 것.
  집행 불가 목록에 *범용 기자재(카메라)* 가 있어 웹캠은 걸릴 수 있으나, **보드 전용 모듈은 부품으로 통과**됩니다.
  RPi5는 CSI 2포트라 카메라 2대가 그대로 붙습니다. (단, RPi5는 **22핀 미니 FPC** — 기존 15핀 케이블 안 맞음)
- **"1회 결제 3만원 이하"가 재료비에도 적용되는지 확인.**
  적용되면 라즈베리파이 구매 자체가 막힙니다. → 교수님/사업단 확인 필요

## 5. 역할 분담 재조정

신청서 그대로 나누면 **B(영상 모델 + 웹)가 A(펌웨어 + 표시부)보다 2배 이상** 무겁습니다.
신청서에 "공통" 항목이 있으므로 아래처럼 재분배합니다.

| 담당 | 범위 |
|---|---|
| **A** | 아두이노 펌웨어 · 시연 표시부 하드웨어 · **QR 웹 프런트** · 부스 시연 세트 · 실측 데이터 수집/집계 |
| **B** | 카메라 설치 설계 · 검출 파이프라인 · ROI/히스테리시스 · 폴백 로직 · 정확도 분석 |

> 시연 질의응답에서 **본인 담당 코드를 설명하지 못하면 기여도 계수(0.7~1.1) 감점**입니다.
> 경계는 처음부터 명확히 갈라 두세요.

## 6. 기업 자문 — 일정이자 점수입니다

신청서에 **특강 1회 · 중간 설계 검토 · 프로토타입 피드백 · 최종 평가**를 쓰고,
*자문이 설계에 어떻게 반영되었는지 최종 보고서에 명시*하겠다고 약속했습니다.

> 회의 때마다 **`docs/기업자문_YYYYMMDD.md`로 즉시** 남기세요. 나중에 복원 안 됩니다.

### 중간 검토 때 물어볼 것 (미리 준비하면 자문의 질이 달라짐)

1. **실무 성능 검증 기준** — 어떤 지표로 합격을 판정하는가
2. **가림 상황의 후처리 관행** — 실제 제품에서 어떻게 처리하는가
3. **카메라 설치 각도·높이 경험치**

> 의료영상분석 회사라 이 세 가지는 실제 노하우가 있습니다.

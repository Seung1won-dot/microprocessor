> **결정 ② IR 빔브레이크를 폐기한다. 센서는 카메라 2대뿐이고, 인터럽트는 아두이노 내부 타이머·UART로 간다.**

> **표시 방식에 관해서는 이 문서가 최신입니다.** 이전 문서의 "입구 LED 신호등" 서술은 전부 무효입니다.

## 2. 왜 뺐나

1. **식당 설치 협의가 프로젝트 전체의 병목** ([실행계획_0914](05_실행계획_0914.md) 1절 ④).
   카메라 설치 허가만으로도 쉽지 않은데, **전원·배선·고정이 필요한 표시 장치**까지 얹으면 승인 난이도가 올라갑니다.
   협의 대상을 **카메라 한 건**으로 줄입니다.
2. **학생이 실제로 쓰는 건 웹입니다.** 입구 LED는 이미 식당 앞에 도착한 사람에게만 보이고,
   우리 과제의 목적은 *"가기 전에 판단"* 입니다. 입구 표시는 목적에 직접 기여하지 않습니다.
3. **비용·공수 회수** — 고휘도 LED·MOSFET·외부 전원·실외형 하우징이 통째로 빠집니다. (3절)

## 3. 대신 ④ 액추에이터는 이렇게 채운다 — **빼면 반려입니다**

> 캡스톤디자인_전체정리 2-1절: 네 단계 중 **하나라도 빠지면 제안서 반려**.
> 반려 유형에 **"앱만 있는 프로젝트"** 가 명시되어 있어, 출력이 웹뿐이면 그대로 걸립니다.

**시연 표시부** — 아두이노 보드에 붙는 소형 표시 장치. **식당에 설치하지 않고, 부스·중간/최종 시연에서만 씁니다.**

| 구성 | 핀 | 역할 |
|---|---|---|
| 신호등 LED 녹·황·적 | D4 / D5 / D6 | 현재 3단계 상태 |
| 4자리 7세그먼트 + 74HC595 | D10 / D11 / D12 | **빈 좌석 수** 실시간 표시 |
| 능동 부저 | D9 | 단계 **전환 시점**에만 짧게 (상시 소음 없음) |

**이 구성의 장점**

- **3주차 실습(74HC595 · 7세그먼트 · 핀 확보 전략)과 그대로 연결됩니다.** 수업 내용을 과제에 쓴 지점이라 보고서·시연에서 점수가 됩니다.
- 워치독 안전 상태(황색 점멸)·AI 폴백 시연이 **그대로 유지**됩니다.
  라즈베리파이 전원을 뽑아도 아두이노가 자체 시계와 EEPROM 평균만으로 표시부를 계속 구동하는 장면이 폴백의 직접 증거입니다.
- 설치 허가·외부 전원·방수 하우징이 **전부 불필요**해집니다.

**핀 재계산** — 시리얼 2 + LED 3 + 부저 1 + 74HC595 3 = **9핀 / 20핀, 여유 11핀.**
외부 인터럽트 핀 **D2·D3는 비워 둡니다** — 나중에 센서를 추가할 여지를 남기기 위해서입니다.

## 3-2. 빔브레이크를 뺀 뒤 인터럽트 요건 — **세 겹으로 쌓는다**

> 캡스톤디자인_전체정리 2-2절: **최소 한 곳 이상 인터럽트 사용, 어디에 쓸지 제안서에 명시.**
> 기존 논거였던 *"출입 통과 0.3초 → 폴링 누락"* 은 센서와 함께 사라졌으므로 **전부 새로 세웁니다. 부품 추가는 0원입니다.**

| # | 인터럽트 | 주기·조건 | 하는 일 | **폴링으로는 안 되는 이유** |
|---|---|---|---|---|
| 1 | **Timer2 CTC (~2ms)** | 고정 주기 | **7세그먼트 4자리 멀티플렉싱** | 자리 전환이 수 ms 단위다. `delay()`로 돌리면 숫자가 깜빡이고, 그 사이 도착한 시리얼 패킷을 통째로 놓친다 |
| 2 | **Timer1 CTC (1초 틱)** | 고정 주기 | ① 워치독(마지막 수신 후 경과) ② **운영시간 경계 판정(오픈·마감)** ③ 황색 점멸 타이밍 | 표시 갱신·수신 처리 중에도 시간은 흘러야 한다. 블로킹 코드와 공존할 수 없다 |
| 3 | **UART RX 인터럽트** | 비동기 | 라즈베리파이 패킷 수신 → 버퍼 적재 + **수신 시각 기록** | 호스트 송신 시점은 우리 `loop()`와 무관하다. 세그먼트 스캔 중에 폴링하면 유실된다 |

**①이 ③을 필요하게 만들고, ③이 ②를 필요하게 만듭니다.** 세 개가 서로 맞물려 있어서
*"왜 인터럽트여야 하는가"* 에 **한 문장으로 답이 됩니다** — 표시 갱신·시각 관리·수신을 동시에 보장해야 하기 때문입니다.

### 운영시간(오픈·마감) 처리 — Timer1 1초 틱 안에서

```
Timer1 CTC 1초 틱 ISR
  ├ tick++                     ← 라즈베리파이와 무관한 독립 시계
  ├ 오픈 시각 도달  → 상태 = 운영중   · 표시부 점등 · 호스트에 추론 시작 요청
  ├ 마감 시각 도달  → 상태 = 운영종료 · 표시부 "CLOSE" · 호스트에 추론 중지 요청
  └ 마지막 수신 후 경과 검사  → 3초 / 15초 단계별 폴백 (3-3절)
```

- **시각 동기는 라즈베리파이 패킷에 `HH:MM`을 실어** 보내고, UNO는 1초 틱으로 자체 유지합니다.
  → **RTC 모듈 불필요 (0원).** 라즈베리파이를 뽑아도 마지막 동기 시각 + 1초 틱으로 시계가 계속 갑니다.
- 운영시간 밖에는 **혼잡도를 표시하지 않습니다.** 닫힌 식당에 "여유"를 띄우는 것이 더 나쁜 오류이기 때문입니다.
- 운영시간 밖에 **추론을 멈추면** 라즈베리파이 발열·전력도 같이 줄어듭니다.

> ⚠️ **제안서에는 ①②③을 다 적되, 주 논거는 ①과 ③으로 두세요.**
> 오픈·마감은 하루 2번이라 *"폴링으로도 잡힌다"* 는 반박이 가능합니다.
> **운영시간은 "인터럽트가 필요한 이유"가 아니라 "1초 틱 인터럽트가 이미 있으니 거기서 처리하는 기능"** 으로 설명하는 것이 안전합니다.

## 3-3. AI 3초 폴백 재정의 — 출입 카운트 없이

```
정상          → 검출값으로 3단계 갱신
3초  무갱신   → 마지막 유효값 유지 + 웹·표시부에 "갱신 지연" + 경과 시간 표시
15초 무갱신   → EEPROM의 요일·시간대별 평균으로 전환 + "확인 불가(추정)" · 황색 점멸
운영시간 밖   → "운영 종료" (혼잡도 표시 안 함)
원칙          → 애매하면 더 혼잡한 쪽 (헛걸음 손실이 더 크다)
```

**EEPROM 요일·시간대별 평균 테이블**이 출입 카운트를 대신합니다.
운영 기간에 수집한 평균값을 UNO의 EEPROM에 써 두면, **라즈베리파이 없이도** *"지금 12:30이면 보통 혼잡"* 을 추정할 수 있습니다.

> 💡 **시연 장면은 그대로 살아납니다.** 라즈베리파이 전원 차단 → 3초 뒤 "갱신 지연" → 15초 뒤 황색 점멸 + EEPROM 평균 추정.
> 출입 카운트 폴백과 **동등한 시연 효과**이고, EEPROM 사용도 수업 범위 안입니다.

## 5. 신청서와 달라지는 점 — 미리 설명해 둘 것

제출한 신청서([신청서_요약서](03_신청서_요약서_0910.md))에는 **"식당 입구 소형 LED 신호등"** 과
산출물 **"아두이노 LED 신호등부 1식"** 이 명시되어 있습니다. 제안서 심사에서 대조될 수 있으므로 **먼저 말하는 편이 안전**합니다.

> **설명 문구 (제안서·구두 공통)**
> "표시 채널을 QR 모바일 웹으로 단일화했습니다. 식당 내 표시 장치는 설치 허가·전원 확보가 필요해 일정 위험이 컸고,
> 학생이 이동 전에 판단한다는 과제 목적에는 웹 채널이 직접 기여합니다.
> 필수 요건 ④ 액추에이터는 아두이노가 구동하는 상태 표시부(신호등 LED · 7세그먼트 빈 좌석 수 · 부저)로 충족하며,
> 이는 AI 폴백 시연 장치를 겸합니다.
> 또한 출입구 계수용 적외선 센서를 제외하고 **좌석 점유 판정을 카메라 2대로 일원화**했습니다.
> 출입 계수는 원래 보조 지표였고, 기업이 지적한 *'출입구 계수는 남은 자리를 모른다'* 는 한계를 우리도 그대로 안고 있었기 때문입니다.
> 인터럽트 요건은 **7세그먼트 멀티플렉싱(Timer2) · 워치독 및 운영시간 관리(Timer1) · 시리얼 수신(UART RX)** 세 곳으로 충족하며,
> AI 폴백의 대체 지표는 **EEPROM에 저장한 요일·시간대별 평균**으로 대신합니다.
> **측정 방식과 AI 설계는 신청서와 동일합니다.**"

- 요지: **주제 변경이 아니라 출력 채널·센서 구성 조정**입니다. 측정 대상(좌석 점유)·AI·검증 방법은 그대로입니다.
- ⚠️ 인터럽트와 폴백은 **요건은 그대로 충족하되 수단이 바뀌었으므로**, 제안서에 **바뀐 설계를 명시**해야 합니다.

| 11 | 5V 2A 어댑터 + DC 잭 터미널 | 1 | 시연 세트 독립 전원 | 8,000 |
| | **소계** | | | **약 50,000~75,000** |

> 🗑 **적외선 빔브레이크는 목록에서 빠졌습니다** (9/21 결정 ②). 인터럽트는 부품 없이 타이머·UART로 갑니다 → 3-2절.
> ⛔ **RTC 모듈도 사지 않습니다.** 시각은 라즈베리파이 패킷으로 동기하고 UNO가 1초 틱으로 유지합니다.

> 💡 **1~11번은 전부 3만원 이하 단품**이라 "1회 결제 3만원 이하" 규정에 걸리지 않습니다.
> 즉 **예산 확인이 늦어져도 이쪽은 먼저 풀립니다.**

### 6-2. 보류 — 호스트가 정해진 뒤에 산다

| 품목 | 왜 지금 못 사나 |
|---|---|
| 라즈베리파이 본체 | **A/B/C안 미확정.** Pi 5(14~16만) ↔ Zero 2 W(2.5~3만) ↔ 학과 대여 |
| **CSI 카메라 모듈 ×2 + 케이블** | ⚠️ **케이블 규격이 보드마다 다릅니다.** Pi 4 = 15핀 / **Pi 5·Zero = 22핀 미니 FPC**. 보드 전에 사면 못 씁니다 |
| microSD | **저장장치 집행 가부 확인 중** ([예산회의 5절 #3](06_예산회의_0916.md)) |
| 방열판·케이스·전원 어댑터 | 보드 모델에 종속 |
| 거치대·브래킷 | **완제품 집행 불가** 우려 → 브래킷·프로파일 등 **재료성**으로 구성해야 함 |

### 6-3. 주문할 때 걸리는 규정 2가지

1. **배송비는 예산으로 못 냅니다.** 3만원 이하로 쪼개 여러 번 주문하면 배송비가 그만큼 **자비**가 됩니다.
   → 6-1을 **한 번에 묶어** 무료배송 기준(보통 3~5만원)을 넘기는 편이 유리합니다.
2. **주말·공휴일·22~05시 결제 불가 · 사업단 카드 대면 수령.**
   → **평일 낮**에 카드를 받아 그 자리에서 주문해야 합니다. 장바구니를 미리 만들어 두면 수령 당일에 바로 끝납니다.

> ✅ **오늘 할 것: 6-1을 디바이스마트 장바구니에 담아 총액 스크린샷 → 제안서 BOM 표에 그대로 붙이기.**
> 심사용 BOM은 [예산회의 4-5절](06_예산회의_0916.md)대로 **"학과 대여 시 0원 · 불가 시 자체 구매"** 조건부로 씁니다.
